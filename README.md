# HANA뿐인 PX — 나라사랑카드 혜택 추천 웹서비스

캠페인 부스에서 QR로 접속해 1분 안에 내 군 생활 소비 패턴에 맞는 나라사랑카드 혜택을 찾아 주는 모바일 웹입니다. 운영자는 별도 대시보드에서 참여 현황을 실시간으로 봅니다.

- 단계: 캠페인용으로 배포·운영 완료 (2026년 7월)
- 개발: 1인 개발·배포

## 화면

| 파일 | 역할 |
|---|---|
| `index.html` | 참여자용 테스트. 10문항 → 소비 유형 판정 → 추천 혜택 4개 → 앱 연결 |
| `dashboard.html` | 운영자 대시보드. 총·당일 참여자, 유형 분포, 추천 혜택 순위, 앱 전환, 최근 참여 내역 |
| `data.js` | 문항·소비 유형(6)·혜택(22) 데이터. 화면 코드와 분리해 내용만 바꿔 재사용 |
| `config.js` | Supabase 프로젝트 URL·공개 키, 테이블 이름, 앱 연결 링크 |
| `supabase/schema.sql` | 테이블, RLS 정책, 클릭 기록 함수 |
| `style.css` | 모바일 우선 반응형 스타일 (720px 이상 2단) |

## 추천 방식

각 선택지에 소비 유형 점수와 관련 혜택이 붙어 있습니다. 응답 점수를 합산해 가장 높은 유형을 결과로 정하고, 그 유형에 지정된 혜택 4개를 보여 줍니다. 지정이 없으면 응답에서 많이 선택된 혜택 순으로 채웁니다.

## 데이터 저장과 접근 권한

```
참여자 브라우저 ──insert──▶ hana_px_results   (조회·수정 불가)
                └─rpc px_mark_oneq_clicked(client_ref)   (클릭 여부 한 칸만 변경)
운영자 ──Supabase Auth 로그인──▶ select (px_admins 등록 계정만, RLS)
```

- 비밀번호는 코드에 두지 않습니다. 운영자 인증은 Supabase Auth가 처리합니다.
- 결과 조회 권한은 브라우저가 아니라 DB의 RLS 정책이 결정합니다.
- `config.js`의 키는 브라우저에 공개되는 publishable 키입니다. 데이터 보호는 RLS가 담당합니다.
- Supabase에 연결하지 못하면 결과를 브라우저 저장소(localStorage)에만 남기고, 대시보드도 그 브라우저 데이터만 보여 줍니다.

## 설정

1. Supabase 프로젝트를 만들고 SQL Editor에서 `supabase/schema.sql`을 실행합니다.
2. Authentication > Users에서 운영자 계정을 만들고, `schema.sql` 맨 아래 주석의 insert 문으로 `px_admins`에 등록합니다.
3. Authentication > Providers(또는 Sign In / Up 설정)에서 공개 회원가입을 끕니다.
4. `config.js`에 프로젝트 URL과 publishable 키를 넣습니다.
5. 정적 호스팅(GitHub Pages 등)에 저장소를 그대로 올립니다. 빌드 과정은 없습니다.

## 저작권·브랜드

캠페인 주최 측의 로고·캐릭터 이미지와 전용 서체 파일은 이 저장소에 포함하지 않았습니다. 해당 자리는 텍스트와 이모지로 대체했습니다. 혜택 문구는 캠페인 당시 기준이며, 실제 카드 혜택은 카드사 공식 안내를 따릅니다.
